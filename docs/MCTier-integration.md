# MCTier 联机

BCCL 主导航新增“联机”。界面使用启动器原有的 WPF 卡片、按钮、下拉框和主题资源，支持浅色、深色和玻璃设置；页面内容可滚动。常规提示、邀请解析错误、复制反馈、组件下载状态都在卡片内显示，不弹出确认窗口。新页面不加载 MCTier 的公告、广告、赞助提示、自动更新窗口或其他工具窗口。

## 使用

1. 在 BCCL 联机首页选择“创建大厅”，直接填写房间名称。输入停止约 0.25 秒后自动检测；名称可用时会临时保留，重名会在名称下提示。点击创建会立即推进并复用正在进行的检测，不重复取消后重新连接。名称留空时，点击创建前自动生成并检测。密码没有长度或字符组成要求，可以为空、单个字符、纯数字、符号、中文或保留首尾空格；空密码表示知道名称的人即可加入。
2. 房主进入 Minecraft 世界，选择“对局域网开放”，记下游戏显示的端口，填入表单并创建。无论选择哪种连接方式、是否启用名称检测，创建动作均使用 `runas` 请求 Windows 管理员权限；拒绝授权就不创建。创建成功后把房间名称（及自己设置的密码）告诉朋友，或复制邀请；同时告知 Minecraft 游戏端口。
3. 朋友选择“加入大厅”，直接输入房间名称，有密码再填写密码。也可以展开“使用邀请链接加入”，粘贴邀请后点击加入，自动读取名称和密码。双方需使用同一名称服务、相同名称/密码与相同 EasyTier 节点。
4. 看到房主成员后，选择房主，填写房主的游戏端口，点击“连接游戏”。复制页面提供的 `127.0.0.1:端口`，填到 Minecraft → 多人游戏 → 直接连接。

联机首页默认只展示创建/加入两个入口。昵称、节点、连接方式和本机开放端口放在默认收起的“联机设置”中。进入大厅后显示邀请与网络状态，以及分步游戏连接操作；房主的“连接朋友的游戏”区域默认收起，需要时仍可展开。左侧说明栏固定为 180 像素，避免长文本挤占操作区。

## 名称检测与兼容

默认通过 `wss://mctier.pmhs.top/signaling` 的 v3 注册协议检测并保护名称。填写名称时建立一个未公开的临时房间成员，保留名称及虚拟地址；修改名称/密码或离开创建页会释放旧的保留。创建时直接使用保留的地址启动核心，无需等待 DHCP，也无需再建立一次 TLS 连接来替换预检成员。加入时先登记并分配不冲突的地址，再启动核心。启动阶段快速读取本机地址确认就绪，就绪后恢复常规刷新；仍以真实核心响应为准，不通过提前显示成功来加速。服务在同一把准入锁内判断名称是否存在，所以两个客户端同时创建同名房间时只会有一个成功，不依赖公开房间列表或密码猜测。

重名范围是**当前名称服务中的在线房间**，不是所有互联网虚拟网络。最后一位成员离开后名称可再次使用。服务无法连接、超时或返回格式错误时，只提示检测失败，不显示名称可用；不会自动跳过检测创建。名称服务中断后，受管理房间会退出并提示重新连接，防止失去名称保护时继续误报正常。

在“联机设置”中可更换名称服务，或取消“检测并保护房间名称”使用直接组网。直接组网保留旧版 BCCL 的网络身份和原有流程，不校验名称占用；连接本次升级前的 BCCL 房间时使用此模式。新导出的邀请标记其组网方式，受管理邀请也携带名称服务地址，导入时自动恢复。

受管理房间使用 MCTier 的 `MCTier-` 网络名前缀，并在名称服务登记真实的 `10.126.126.x` 地址；其他虚拟网段使用直接组网。房间名称、昵称、网络凭据与虚拟地址通过 TLS 发送给选择的名称服务，以执行准入与密码校验，不写入本地日志或偏好文件。普通密码保持原值，兼容已有房间；超过底层 256 字节或包含控制字符的密码自动派生为固定长度的兼容凭据，邀请、名称服务、EasyTier 与其他功能鉴权使用一致的凭据，不截断原密码。手动输入原密码或使用邀请均可加入。

“核心运行中”只表示本地核心启动；虚拟地址分配后才显示网络就绪，发现远端成员后才显示远端人数。“本机游戏入口已准备”表示本地 TCP 转发监听已创建，最终游戏服务器可达性由 Minecraft 连接结果判断。

## 两种模式

- **MC 联机（默认；加入无需管理员）**：使用 EasyTier 的 no-tun、smoltcp，不创建系统网卡；受管理房间使用名称服务保留的地址，直接组网仍使用 DHCP。创建房间始终申请管理员权限，加入房间不额外提权。允许从虚拟网络访问填写的本机游戏端口与 BCCL 其他功能的 TCP 39257 端口；加入其他玩家的 Java 版游戏使用本机 TCP 转发入口。SOCKS 门户、其他功能监听与游戏入口只绑定回环地址。此模式不提供系统级虚拟 LAN 或基岩版 UDP 游戏入口。
- **虚拟局域网（系统授权）**：使用 Wintun 创建 `BCCL-MCTier` 虚拟网卡，创建与加入均申请管理员权限。拒绝授权时不会继续启动核心。此模式允许同一虚拟网络中的成员访问本机网络服务，具体可达性仍由系统防火墙决定。

管理员权限由独立辅助进程申请，主界面保持原权限。辅助进程会核验实际管理员令牌，避免请求提权失败后仍误报创建成功；等待 Windows 授权期间不阻塞主界面或名称保留心跳。Windows 是否显示确认框受当前进程权限及系统 UAC 策略控制，程序不修改这些系统设置。

控制通道使用显式用户/管理员 ACL，拒绝网络身份，并在两端通过 Windows 管道 API 核验对端进程 ID。这里不使用 `PipeOptions.CurrentUserOnly`：Windows 下该选项还检查提权等级，会阻止普通启动器和已提权辅助进程通信。辅助进程保留父进程启动时间核验，客户端仅提供 Identification 级别，未开放 Everyone 访问。

完整模式可在游戏中直接使用成员虚拟 IP 与游戏端口。当前没有移植 MCTier 的 Minecraft 广播发现桥，建议使用直接连接。公共大厅广场与二维码界面不在本次范围内。

## 其他功能（Beta 0.1.0）

联机左侧新增“其他功能”，提供聊天室、文件共享、语音通话、屏幕共享和远程控制。功能使用 BCCL 原生 WPF 页面与 EasyTier 加密网络，无需启动原版 MCTier 窗口，也不加载原版广告或新手弹窗。新增功能是 BCCL 两端协议，双方需使用 BCCL Beta 0.1.0 及以上支持此协议的版本；原版 MCTier 的聊天室/WebRTC 与这些功能不直接互通。游戏网络、邀请和名称服务仍按上述方式兼容。

- 聊天：消息在本次启动器会话中显示，不写聊天日志。发现同一房间的 BCCL 成员后自动建立连接。
- 文件：选择本地文件进行分享，接收方主动选择并接收后才开始传输。使用分块流式读写、长度与 SHA-256 校验；未完成的临时文件在断线或取消接收后清理，接收文件使用唯一前缀，不覆盖既有文件。可停止全部文件分享，也可取消全部接收。文件保存到运行数据目录 `Multiplayer/ReceivedFiles`。
- 语音：单独控制收听与麦克风，均默认关闭。使用 Windows 默认设备、16 kHz/16-bit 单声道 PCM 和缓冲播放；建议使用耳机。该基础语音通道没有原版 WebRTC 的回声消除或 Opus 编码。
- 屏幕：主动开启后共享主显示器，目标每秒 60 帧，JPEG 不超过 960×540。优先使用 DXGI Desktop Duplication，在显卡上缩小后读取画面；不支持时回退到 GDI。独立线程采集，发送和采集并行；最多一帧正在发送、一帧等待且后者始终替换为最新画面，网络慢时丢弃过时帧。接收端合并待显示帧、后台解码，页面显示实际显示帧率。发送与接收两端都建议更新到本次构建。实际帧率取决于设备、桌面更新速度和网络，不保证所有场景固定 60 帧。
- 控制：先由被控方开启屏幕共享，再在页面内明确允许请求；每次授权产生独立随机令牌，绑定连接中的成员，15 分钟后失效。被控方可点击停止或按全局 `Ctrl+Alt+F12` 立即收回；无法注册停止快捷键时不授权。未授权、过期或已撤销的输入会被拒绝。断线/停止共享释放按下的键与鼠标按钮。不支持操作 Windows 提权界面，也不转发 Windows 键。

切出“其他功能”页面会停止麦克风、收听、屏幕共享与远程控制；大厅网络和已同意的文件传输继续。断开大厅会关闭其他功能服务。其他功能端口冲突仅在页面内提示，不阻断游戏联机；此端口不能同时作为本机游戏端口。

其他功能服务使用双向随机挑战和房间凭据 HMAC 验证，再进行有长度上限的消息交换。每条连接串行写入，文件以小块发送，与语音、聊天共用加密隧道；有连接数、帧大小、并行文件数和临时接收限制。屏幕未变化时发送很小的重复帧标记，复用接收端已有画面；停止共享清除缓存。旧接收端忽略重复标记仍可保留上一幅画面，新画面与停止消息保持兼容。与原版服务协议不同，不会把聊天、文件、音频或屏幕转发给名称登记服务。

切换启动器页面保持联机。断开或关闭启动器会关闭私有控制管道，辅助进程随后终止自己创建的 EasyTier 核心；不会按进程名关闭其他软件的核心。辅助进程也监听父进程退出，处理启动器异常退出时的清理。

## 组件和数据

- 页面：`BCCL/Pages/PageMultiplayer`。
- 会话与辅助进程：`BCCL/Modules/Multiplayer`。
- 音频与桌面适配：`BCCL/Modules/Multiplayer/Extras`。
- 其他功能网络协议、文件收发：`BCCL.Core/Link/MCTier/Extras`。
- 邀请、核心控制、组件准备、端口桥：`BCCL.Core/Link/MCTier`。
- 单元测试：`BCCL.Core.Test/Link/MCTier*Test.cs`。
- 独立验证：`scripts/MultiplayerVerification`。
- 偏好：启动器运行数据目录下 `Multiplayer/preferences.json`，保存昵称、节点、连接模式和名称服务选项，不保存房间密码。
- 核心组件：用户本地应用数据目录 `BCCL/MCTier/Runtime/2.6.4`。优先复用启动器已安装的 EasyTier。缺失组件从 EasyTier 官方发行包获取，Wintun 缺失时从官方包获取，下载包以固定 SHA-256 校验后才解压。不会把原上传压缩包中的脚本作为安装指令执行。
- 兼容网络凭据通过私有命名管道交给辅助进程，再通过子进程环境变量交给核心；不发送无须传递的原始长密码，不放在命令行或诊断日志中。邀请是可移植的访问凭据，持有邀请的玩家可以加入对应房间。

验证产物放在工作区上级 `Temp/MCTier-integration`，修改前文件放在 `Backup/MCTier-integration-20261111`，交付记录放在 `Reports`。
